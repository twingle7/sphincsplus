# Poseidon2-SPHINCS+-Fischlin 技术创新点整理

## 创新点框架

### 一、密码学层面创新

#### 1.1 Poseidon2 对 SPHINCS+ 的系统性替换
- **问题**：SPHINCS+ 标准的 SHA-256/SHAKE-256 哈希在 STARK/SNARK 电路中代价极高（R1CS >27,000 约束/次 SHA-256）
- **方案**：使用 Goldilocks 域 (p = 2^64 - 2^32 + 1) 上的 Poseidon2（t=12, capacity=6, rate=6, RF=8, RP=22）全量替换
- **关键设计决策**：
  - Goldilocks 域选择：64-bit 友好，适合 C uint64_t 和 STARK 算术化，2^32 阶单位根支持 FFT
  - 域分离策略：6 种 domain tag 确保不同类型的哈希调用不可混淆
  - 字节到 lane 编码：pad10*1 + 小端序打包
- **与现有方案区别**：SPHINCS+-SM3 替换了另一个传统哈希（SM3），但 Poseidon2 是专为 ZKP 优化的

#### 1.2 THF 语义的完整保持
- SPHINCS+ 安全证明依赖 THF 的四个性质（SM-TCR/SM-DSPR/SM-PRE/SM-UD）
- Poseidon2 替换后保持了 pub_seed || ADRS || M 的完整 THF 语义
- 参数选择遵循 SPHINCS+ 规范的标准方法

### 二、协议层面创新

#### 2.1 Fischlin 框架在 Hash-Based 签名上的首次实例化
- Fischlin (CRYPTO 2006) 是通用框架，但此前多用于 RSA/离散对数/DL-based 签名
- SPHINCS+ 的非平凡 witness 结构（多层 Merkle 树 + FORS + WOTS+）使实例化有实质性技术挑战
- 具体处理：
  - Commitment：Poseidon2 哈希（非代数结构，与 RSA blind 根本不同）
  - sigma_C 构造：c = (pk_E, com, sigma_com; omega2) — 将 SPHINCS+ 签名嵌入类密文结构
  - 展示证明：STARK 证明代替 Fischlin 原框架中的 NIZK PoK

#### 2.2 Statement-Bound 模式
- 在标准 Fischlin 框架外增加了 Statement-Bound 变体
- 将展示绑定到 pk_E, m_pub 等显式公共声明
- 增加了抗重放和上下文绑定的安全性

### 三、工程/系统层面创新

#### 3.1 全内生 AIR（核心新增，论文后工作）⭐⭐⭐
- **核心理念**：trace = verification 的全过程。证明 trace 正确 = 证明验证通过
- **技术方案**：
  - trace builder 遍历 crypto_sign_verify 的完整执行路径
  - 预计算 nxt_expected = poseidon2_round(current_state) 存储在 trace 列 16-27
  - AIR 仅需简单等式约束 `nxt == expected`，无需在 AIR 中实现复杂的原位计算
- **约束极简**：16 个约束（vs. SHA-256 AIR 通常需要数千约束）
  - 6 rate lanes 正确性
  - round counter 正确递增
  - permutation index 在排列间递增
  - call type 在排列内不变
  - pad flag 约束
- **关键指标**（dev params n=16, h=40, d=4）：
  - Trace: 131,072 rows × 64 columns
  - 3,686 Poseidon2 permutations
  - Proof: ~95 KB, ~127 seconds
  - Column utilization: 25% (64/255)

#### 3.2 成本模型驱动的参数搜索
- 解析公式：total_perms = H_msg + FORS + HT
- trace_rows = next_pow2(total_perms × 32)
- prove_seconds ≈ 127 × (trace_rows/131072) × (log₂(trace_rows)/17)
- ~3.5% 误差（dev params），~50x 加速 vs 全量 benchmark

#### 3.3 C/Rust FFI 双语言架构
- C 侧：签名、哈希、Fischlin 协议流、witness 构造
- Rust 侧：Winterfell STARK prover/verifier、AIR 引擎、trace builder
- FFI：ABI 版本检查、结构化错误码映射
