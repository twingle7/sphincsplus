# 技术交底书

## 发明名称

基于全内生AIR的哈希后量子签名盲签名方法及系统

## 交底日期

2026年7月23日（更新版；初版 2026年7月15日）

## 一、技术领域

本发明属于密码学技术领域，具体涉及一种基于STARK证明系统和全内生代数中间表示（AIR）的盲签名方法及系统，适用于NIST已标准化的三类哈希后量子签名方案——SPHINCS+（SLH-DSA，FIPS 205）、XMSS（SP 800-208）和XMSS^MT/HSS（SP 800-208）。

## 二、背景技术与要解决的技术问题

### 2.1 技术背景

NIST已标准化三类基于哈希的签名方案：
- SPHINCS+（FIPS 205）：无状态，适用于通用场景
- XMSS / XMSS^MT / HSS（SP 800-208）：有状态，适用于嵌入式/固件场景

这些方案安全假设保守（仅依赖哈希抗碰撞性），但不支持盲签名——签名直接暴露签名者身份和消息内容。

Fischlin（CRYPTO 2006）提出了通用盲签名框架（Commit → Issue → Show → Verify），将盲签名转化为承诺+签名+展示证明。核心挑战在Show阶段——如何在不暴露完整签名的前提下证明签名有效。

Bouillaguet等人（IEEE S&P 2026）从理论上证明任意Hash-and-Sign签名可编译为Fischlin盲签名，并实现了UOV和Wave两种方案的具体实例化，使用MPC-in-the-Head作为证明系统。Herranz和Louiso（ePrint 2025/2097）首次探索了纯哈希盲签名的可行性，使用MSS（有状态Merkle签名方案）+ ZKBoo（MPC-in-the-Head变体）进行了原型验证，但仅给出电路规模估算，未实现完整系统。

### 2.2 现有技术的不足

| 路径 | 代表方案 | 核心问题 |
|------|---------|---------|
| 基于格 | del Pino-Katsumata (CRYPTO 2022), Beullens et al. (CCS 2023) | 依赖结构化代数假设（Ring/Module SIS/LWE），长期安全边际不定 |
| MPCitH + 通用哈希 | Herranz-Louiso 2025, Bouillaguet et al. CAP 2026 | 电路门数高达数万，证明体积大（~MB级），未使用ZK友好哈希 |
| 配对 | BBS+ (BLS12-381) | 不抗量子 |
| 外部守卫 | 传统混合证明模型 | ZK证明语义不完整——验证者需信任外部C语言检查 |

### 2.3 本发明要解决的技术问题

1. 如何将SPHINCS+/XMSS/XMSS^MT/HSS签名验证的**全部**密码学运算**内生地**纳入STARK证明电路，消除对外部C语言guard的依赖
2. 如何在STARK电路中避免Poseidon2的x^7 S-box和MDS矩阵乘法的高次多项式约束
3. 如何以**常数级别**的约束数（53条，全部代数度数为1）实现完整的签名验证证明——而非数万条
4. 如何使同一套AIR约束适配SPHINCS+、XMSS、XMSS^MT/HSS三种NIST标准哈希签名方案
5. 如何将C语言中面向对象的海绵状态管理（跨多次置换调用）映射到二维执行跟踪矩阵并保持状态连续性

## 三、技术方案详述

### 3.1 总体协议流程

```
Holder (持有者)                  Issuer (签发者)             Verifier (验证者)

① 选择随机数r

③ 凭证最终化：
   σ_com = σ_blind (verbatim，不进行数学去盲)
   构造密文: σ_C = Poseidon2_Sponge(pk_E || c || σ_com || ω2)

```

### 3.2 核心创新：全内生AIR的STARK证明生成方法

#### 创新点1：执行跟踪即验证过程（Trace IS Verification）

执行跟踪构建器（trace builder）模拟`crypto_sign_verify`的完整执行路径：

1. **H_msg计算**：吸收PK.seed、PK.root、消息m → 消息摘要（展开为Poseidon2置换序列）
2. **FORS验证**（SPHINCS+专有；XMSS/XMSS^MT跳过此层）：k棵树，每棵树验证a层认证路径 → k×(a+1)次置换
3. **WOTS+链验证**：d层超树，每条链(w-1)步迭代置换
4. **Merkle认证路径验证**：每层h/d层路径验证

每轮Poseidon2运算对应跟踪中的一行，记录：
- 列0-11：12个状态通道当前值（Goldilocks域元素，p = 2^64 - 2^32 + 1）
- 列4：轮次计数器（0..29，30轮/置换）
- 列5：全局置换索引（0..2090，在置换边界递增）
- 列6：调用类型标识（THASH_F=0x11 / THASH_H=0x12 / THASH_TL=0x13 / Commit / SigmaC / ...）
- 列7：填充标记

**关键洞察：** 跟踪的每一行就是SPHINCS+/XMSS验证的一步运算。证明跟踪正确 = 证明验证通过——不需要任何外部C语言guard。

#### 创新点2：预计算期望状态（Pre-computed Expected Next State, PENS）

在构建跟踪的同时，对每一行调用Rust中的`poseidon2_round()`函数：

```
for each row:
    expected[0..11] = poseidon2_round(
        current_state[0..11],
        round_constants[row],
        mds_matrix
    )
    trace[row][col_16..27] = expected[0..11]
```

poseidon2_round()内部执行：
- **外部全轮（RF=8）**：全部12通道 × x^7 S-box + 全MDS矩阵乘法
- **内部半轮（RP=22）**：仅通道0 × x^7 S-box + 对角MDS矩阵乘法

这些计算在证明生成前的本地预处理中一次性完成，**不进入STARK电路**。STARK电路仅需验证"跟踪中记录的下一状态等于预计算的期望值"。

#### 创新点3：仅含等值约束的53条AIR

由于期望状态已预计算并存储在辅助列中，AIR约束全部退化为**度数为1的等值检查**：

**核心置换约束（16条）：**
- 6条rate通道（通道0-5）等值约束：nxt[i] == cur[i+16]
- 6条capacity通道（通道6-11）等值约束：nxt[j] == cur[j+16]
- 1条轮次计数器约束：同一置换内递增，置换边界重置
- 1条置换索引约束：同一置换内保持，置换边界递增
- 1条调用类型约束：同一置换内保持不变
- 1条填充标记约束

**海绵状态连续性约束（12条）：**
- 通过列39（carries_from_prev）和列40（carries_to_next）标志位控制跨置换块的状态传递方向
- 列41-52（init_state）存储每个置换块的初始海绵状态
- AIR约束：若carries_from_prev[i]=1，则init_state[i]等于上一个置换块最终行的输出状态
- 这解决了将C语言面向对象的海绵状态管理映射到二维跟踪矩阵的关键技术难题

**THASH吸收绑定约束（12条）：**
- absorb[0]绑定到domain tag + pub_seed的低字节（通过Lagrange选择器在THASH第一行检查）
- absorb[1]绑定到pub_seed的高字节
- absorb[2..5]绑定到预期的ADRS地址字节（与跟踪构建器预计算值匹配）
- 防止跨公钥伪造和跨地址重放

**THASH吸收验证约束（8条）：**
- 域标签一致性验证
- 地址一致性验证
- 输入来源验证

**布尔约束（4条）：**
- 填充标记、轮次计数器MSB等布尔值约束

**边界断言（6条）：**
- 初始状态/轮次/置换索引断言
- 最终状态断言
- 根节点断言（root_row：计算根 = PK.root）
- 承诺输出断言（row 30：commit输出 = 公开输入com）

### 3.3 跨方案通用性

三种NIST标准化方案共享同一套Poseidon2置换（RF=8+RP=22, t=12），验证路径的差异仅在于FORS层的有无和超树层级数量：

| 方案 | 标准 | 验证路径 | 跟踪构建器适配 |
|------|------|---------|--------------|
| SPHINCS+ | FIPS 205 | H_msg → FORS → WOTS+ → Merkle | 完整路径 |
| XMSS | SP 800-208 | H_msg → WOTS+ → Merkle | 跳过FORS |
| XMSS^MT/HSS | SP 800-208 | H_msg → (WOTS+ → Merkle) × N层 | 跳过FORS + 多层级迭代 |

**AIR约束层完全复用——三种方案使用完全相同的53条约束和6条边界断言。** 仅执行跟踪构建器需要适配各方案的参数配置（n, h, d, k, a, w）和FORS层的有无。这种通用性源于Poseidon2作为统一底层置换的设计——所有方案的THF调用均映射到相同的海绵吸收-挤压操作。

### 3.5 安全性

| 安全假设 | 说明 |
|---------|------|
| Poseidon2抗碰撞性（ROM） | 满足SPHINCS+规范的SM-TCR/SM-DSPR/SM-PRE/SM-UD四项THF性质；30轮远超已知攻击阈值（统计饱和~18轮，Gröbner基~14轮） |
| STARK可靠性（IOP+FRI） | 基于多项式IOP模型和FRI低度测试，27次查询提供~108-bit猜想可靠性 |
| 无需可信设置 | Goldilocks域、MDS矩阵、轮常量均可公开验证生成 |
| 抗重放 | ctx_hash = Blake3(pk_sig || pk_E || com || m_pub || public_ctx || σ_C)，296字节嵌入proof header |

**四层模块化安全归约链：**

```
Poseidon2 (ROM) → THF四性质 → SPHINCS+/XMSS EUF-CMA → Fischlin OMUF
                                                    (Bouillaguet编译器 Theorem 3)
```
